# backend — платформа на Python

Всё, что работает на сервере, и программа блока, который стоит в шкафу светофора.
Запуск из корня проекта: `python -m urban` (или кнопка ▶ в VS Code).

## С чего начать читать

1. `urban/platform.py` — сердце: получает данные, находит перекосы, готовит предложения.
2. `urban/gateway/gateway.py` — единственный путь к светофорам: правила, решение оператора, аренда команды.
3. `urban/edge/device.py` — что делает блок на перекрёстке, когда получает команду.
4. `urban/api/app.py` — сайт и API: вход, роли, кнопки оператора.

## Что где

| Папка или файл | Что внутри |
|---|---|
| `urban/api/` | сайт и API: вход, роли, все запросы интерфейса |
| `urban/platform.py` | анализ и предложения |
| `urban/gateway/` | правила для команд, аренда, журнал с цепочкой хэшей |
| `urban/analytics/` | очереди на перекрёстках, заторы, отклонения у инженерных объектов |
| `urban/devices/` | реестр блоков, их ключи и подписи, здоровье, смена ключа шлюза |
| `urban/edge/` | программа блока: демо-флот из 32 блоков или один настоящий (`--unit`) |
| `urban/equipment/` | как блок говорит с контроллером: реле по Modbus, NTCIP по SNMPv3 |
| `urban/sensors/` | подсчёт очереди по камерам на самом блоке |
| `urban/sources/` | откуда приходят данные: симуляция SUMO или только часы (режим оборудования) |
| `urban/store.py` | история в SQLite: журнал, команды, замеры |
| `urban/export.py` | копия журнала за пределами сервера и её проверка |
| `urban/accounts.py`, `urban/users.py` | учётные записи, второй фактор; консольная утилита |
| `urban/provision.py` | ключи, сертификаты, учёт блоков |
| `urban/pipeline/` | подготовка карты района из OpenStreetMap |
| `urban/experiments/` | замер: стало ли лучше с управлением |
| `urban/config.py` | настройки из `.env` |
| `tests/` | тесты, по файлу на часть системы |

## Тесты

```bash
cd backend
../.venv/Scripts/python -m pytest -q
```

Тесты SNMPv3 поднимают независимый агент `pysnmp` — он ставится вместе с `backend[dev]` и нужен только для них.
