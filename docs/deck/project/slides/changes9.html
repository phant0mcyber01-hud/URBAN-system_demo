Девятый шаг собирает комплект для первого настоящего мини-ПК на стенде. До него все блоки, записанные с одного образа, имели одинаковые GUID диска и разделов: флешка с тем же образом рядом с диском блока останавливала его загрузку. И весь парк делил один пароль обслуживания GRUB: его хэш, снятый с загрузочного раздела одного блока и подобранный вне сети, открыл бы меню загрузки любого. Теперь os/unit-image.mjs даёт каждому образу случайные GUID и свой пароль: новый хэш попадает во встроенный конфиг загрузчика и в grub.cfg, загрузчик заново подписывается ключом db, grub.cfg — ключом загрузки. Сам пароль лежит только рядом с образом на машине сборки, в файле .grub-password, а оттуда идёт в паспорт блока; в образе и в git его нет. Образ сборки из build.mjs остаётся общим, поэтому блоки пишем только из unit-image. Второе — ключи, которым доверяют блоки в поле: CA обновлений, PK, KEK и db, ключ загрузки, ключ депонирования. Они жили только на этом ноутбуке. keys-backup.mjs упаковывает всю папку ключей в один файл, зашифрованный фразой владельца, одним конвейером tar в gpg внутри контейнера: открытого архива нигде нет, фраза идёт через стандартный ввод, не в командной строке. Проверка доказывает, что неверная фраза ничего не пишет, а верная восстанавливает каждый файл байт в байт. Третье — порядок установки стенда в mini-pc.md: BIOS с fTPM, ключами Secure Boot, паролем и без загрузки с USB и по сети — до первой загрузки; запись Rufus; первая загрузка; копия файла восстановления; две сети и камеры; подключение в центре; пароль GRUB в паспорт. Что открыто, говорим прямо. Сборки подписаны тестовыми ключами; боевые выпускает владелец на машине без сети, и тогда все блоки пишутся заново — это его решение, в шаге 9 оно не сделано. Пароль и GUID на каждый блок проверены только в QEMU; ни один настоящий мини-ПК ещё не запускался.
