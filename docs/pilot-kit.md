# Набор для пилота: обследование и стенд

Два первых шага пилота делаются руками — на перекрёстках и на столе с железом. Здесь то, что для них
подготовлено в коде, и как этим пользоваться. Смысл вопросов и порогов — в [hardware.md](hardware.md), раздел 11.

## 1. Обследование перекрёстков

```bash
python -m urban.survey sheets
```

Создаёт в `data/survey/`:

- `sheets.html` — по листу на каждый из 32 перекрёстков: координаты и ссылка на карту, подъезды, соседи по ходу
  движения и все вопросы списка с полями для ответов. Открыть в браузере и распечатать (каждый лист на своей странице).
- `survey.csv` — таблица для ответов, по строке на перекрёсток. Открывается в Excel; в полях «да/нет» писать
  `да` или `нет`, пустое значит «не проверено».

С собой: распечатка, телефон для фото (шкаф снаружи и внутри, табличка контроллера, каждый подъезд с места будущей
камеры), измеритель уровня LTE. Обследование делать с листвой — летом кроны закрывают обзор.

После объезда:

```bash
python -m urban.survey summary data/survey/survey.csv
```

Покажет простыми словами и сохранит в `data/survey/summary.md`:

- какие контроллеры стоят и сколько каждых;
- какие протоколы встретились и что это значит для нас: для NTCIP и входов выбора плана адаптеры уже есть,
  для GB/T 20999 нет — нужен текст стандарта и контроллер на стенд;
- какие перекрёстки готовы к этапу 1 (камеры и блок, контроллер не трогаем): шкаф в порядке, есть питание,
  место и опора для камеры;
- какие готовы к этапу 2 (управление): то же плюс протокол, для которого есть адаптер;
- чего не хватает по каждому перекрёстку и какие ещё не обследованы.

## 2. Стенд и приёмочные испытания

Стенд: один контроллер, вычислитель блока, плата реле или кабель к контроллеру, камера, ноутбук с платформой
в режиме оборудования (`URBAN_SOURCE=field`). Блок учитывается как обычно ([deploy/README.md](../deploy/README.md)).

### Испытание А — точность длины очереди

На блоке записывать, что он измеряет:

```bash
python -m urban.bench log-queues --sensors /run/urban/queues.json --out queues.csv
```

Наблюдатель в это же время записывает в `observed.csv` столбцы `time, approach, metres` (или `cars` — машины,
пересчитываются по 7,5 м). Время — в секундах эпохи или `2026-07-15T08:30:00`; часы блока и наблюдателя сверить.
Записи нужны днём, ночью и в час пик. Затем:

```bash
python -m urban.bench accuracy --log queues.csv --observed observed.csv
```

Порог: ошибка не больше 15 % или двух машин; испытание пройдено, если в допуске не меньше 90 % наблюдений.
Отдельно выводится смещение — если блок систематически занижает или завышает, это видно сразу.

### Испытания В и Г — откат

```bash
python -m urban.bench rollback --test link --controller 192.168.10.2:161   # В: обрыв связи с платформой
python -m urban.bench rollback --test unit --controller 192.168.10.2:161   # Г: блок обесточен
```

Помощник сам опрашивает контроллер и ведёт по шагам: ждёт, пока вы примените предложение в интерфейсе платформы и
контроллер его включит, просит выдернуть кабель (или обесточить блок) и нажать Enter, засекает, когда контроллер
вернулся к базовому плану. Допустимо: для В — срок аренды (180 с), для Г — таймер самого контроллера
(`--backup-time`, по умолчанию 180 с); плюс 10 с на опрос.

Контроллер читается по SNMPv3 (учётные данные в `SNMP_USER`, `SNMP_AUTH_PASS`, `SNMP_PRIV_PASS`) или по v2c
(`--snmp-version 1 --community ...`). Какой объект показывает «сейчас работает заданный план», зависит от
контроллера: по умолчанию читается `systemPatternControl`, для своего контроллера укажите объект состояния из его
MIB через `--oid`.

### Остальные испытания

- **Б — приватность:** сутки записи сетевого трафика блока (`tcpdump` на внешнем порту) и проверка, что наружу
  уходят только отчёты платформе, без кадров.
- **Д — жара:** шкаф на солнце в июле; температура видна во вкладке «Устройства» и в истории
  (`/api/history/devices/<блок>`), перезагрузки — по счётчику соединений.
- **Е — вскрытие:** открыть дверь шкафа при действующей команде; на платформе — тревога, перекрёсток
  заблокирован, команда снята (видно в журнале).

Для Б, Д, Е автоматического помощника нет: они проверяются наблюдением и уже существующими экранами.
