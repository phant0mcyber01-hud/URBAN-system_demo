# Архитектура пилота

## Принятые решения

1. **Клин пилота**: дорожные события и общественный транспорт в одном районе.
2. **Платформа предлагает, оператор решает.** Платформа сама ничего не применяет. Действие возможно
   только после решения учётной записи с ролью оператора; наблюдатель видит всё, но не решает.
3. **Вне контура реального времени.** Платформа получает данные от источников и не участвует
   в управлении оборудованием; отказ платформы не влияет на работу города.
4. **Command Gateway.** Единственный путь команды к оборудованию. В политике разрешена одна команда
   (перенести до 15 с зелёного между фазами перекрёстка, цикл не меняется). Команда выдаётся как аренда и сама истекает; всё записывается
   в журнал аудита с цепочкой хэшей. Остальные предложения (зелёный коридор, заявки) только записываются.
   В демо оборудование эмулируется, реального транспорта к светофорам нет. Светофоры Ферганы автономны,
   для настоящего управления нужны модули связи на перекрёстках.
5. **Данные в стране.** Всё хранится и обрабатывается локально; карта рисуется из собственных
   слоёв, внешних тайлов и запросов при работе нет.
6. **Protect the city, don't control its residents.** Камеры отдают только агрегаты потока;
   идентификаторы машин не покидают аналитический модуль, лица и номера не обрабатываются.

## Поток данных

```
 симуляция (sources/sumo)            URBAN Edge, отдельный процесс (edge/)
 ├─ датчики очередей ─── /field ───► EdgeDevice ─── отчёты ──► /device (TLS, :8443)
 └─ контроллеры ◄─────── /field ──── EdgeController ◄─ команды с подписью шлюза ─┐
                                                                                 │
 симуляция ──► bus: source.frame ──► Platform.handle                    DeviceHub + реестр
   (машины для двойника,              ├─ analytics/queues   ◄─ очереди из отчётов   │
    события служб, телеметрия)        ├─ analytics/traffic, infra                  │
                                      └─ gateway: политика, решение оператора ─────┘
                                            │
                                            ▼
                                  bus: platform.frame ──► /ws ──► интерфейс
                                  оператор ──► API (сессия) ──► gateway
```

Три сетевых границы и уровень доверия на каждой:

| Граница | Кто | Чем защищена |
|---|---|---|
| `/ws`, `/api/state`, `/api/devices`, `/api/audit` | учётная запись любой роли | вход по паролю, сессия 12 ч, только чтение |
| решения, «Отозвать всё», «Отключить связь» | роль оператора | сессия; подбор пароля блокируется по имени и по адресу |
| отзыв устройств, учётные записи | роль администратора | то же |
| `/device`, порт 8443 | устройства URBAN Edge | TLS, подпись запроса ключом устройства, подписи команд ключом шлюза |
| `/field` | полевой канал демо | только localhost; заменяет кабели в шкафу, в реальности его нет |

Шина (`core/bus.py`) работает внутри процесса платформы. Это место, где в развёртывании появится брокер.
Для замеров и тестов есть встроенный режим: Edge работает внутри процесса симуляции, без сети, чтобы
прогон был детерминированным.

## Что в макете смоделировано

| Часть | Сейчас | В пилоте |
|---|---|---|
| Транспортный поток | симуляция SUMO со случайным спросом | детекторы, GPS общественного транспорта |
| Происшествия и выезды | сценарий в симуляции | данные дежурных служб |
| Телеметрия объектов | генератор с заданной деградацией | SCADA и приборы учёта |
| Камеры | вид двойника, счётчик из симуляции | видеоаналитика на стороне камеры, в платформу только счётчики |
| Анализ | пороги, z-score, линейный тренд | модели, обученные на данных пилота |
| Защита | режим чтения, аудит, локальность | разграничение доступа, шифрование, мониторинг |

## Производительность интерфейса

- Статические слои (здания, дороги, зелень) строятся один раз и не пересобираются по кадрам.
- Транспорт рисуется одной инстансированной сеткой; раз в кадр обновляются только
  типизированные массивы позиций, без создания объектов и без тесселяции.
- Пульсация маркеров сделана через uniform-параметры, атрибуты слоёв не перестраиваются.
- Плотность пикселей ограничена 1.5, чтобы экраны HiDPI не учетверяли нагрузку на видеокарту.
- Сервер отдаёт данные со сжатием gzip; в кадре только машины внутри сцены,
  координаты в целых дециметрах от центра.
- Панель обновляет DOM только при изменении содержимого.

Счётчик внизу слева показывает кадры в секунду, время работы скрипта на кадр и число машин.

## Следующие шаги

- Хранилище (PostGIS) и история событий, воспроизведение сценариев.
- Command Gateway как отдельный сервис с собственной зоной и политиками.
- Реальные маршруты общественного транспорта Ферганы, влияние ДТП на линии.
- Построение маршрута между точками и расчёт времени в пути.
- Аутентификация и роли операторов.
