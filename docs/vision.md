# Зрение блока URBAN Edge

Как блок на перекрёстке превращает видео с камер в длину очереди в метрах — и почему картинка при этом никуда
не уходит.

```
камера (RTSP) ──► кадры в памяти, 4 в секунду ──► нейросеть: рамки машин ──► метры на дороге ──► очередь
                                                                                         │
                                       платформа получает только это: {"J-07-N": 34.5} ◄──┘
```

## Что происходит на блоке

1. **Кадры.** `urban.vision` берёт поток с IP-камеры в сети шкафа (или видеофайл), по умолчанию 4 кадра в секунду.
   Кадр живёт в памяти, пока его смотрит нейросеть, и выбрасывается. Ничего не записывается.
2. **Машины.** Нейросеть YOLOX находит на кадре легковые, автобусы, грузовики, мотоциклы — только рамки в
   пикселях. Людей, лица, номера она не ищет; классы, кроме транспорта, отбрасываются сразу.
3. **Метры.** Калибровка камеры (четыре точки на дороге) переводит рамку в «столько-то метров от стоп-линии, такая-то
   полоса». Короткие обезличенные треки дают скорость: стоит машина или едет.
4. **Очередь.** То же правило, что в демо-двойнике: от стоп-линии назад по стоящим машинам, пока разрыв не больше
   нескольких метров. Самая длинная полоса — очередь подъезда.
5. **Наружу** раз в секунду уходит файл `queues.json` с метрами, блок пересылает его платформе. Если камера молчит
   дольше 5 секунд — по подъезду «нет данных», а не ноль.

## Модель

YOLOX (Megvii, лицензия Apache-2.0), обученная на COCO, в формате ONNX — запускается ONNX Runtime на процессоре
блока или на ускорителе.

| Модель | Вход | Размер | Где |
|---|---|---|---|
| `yolox_nano.onnx` | 416×416 | ~4 МБ | вычислитель без ускорителя, 2–4 кадра в секунду на камеру |
| `yolox_s.onnx` | 640×640 | ~35 МБ | с ускорителем или мощным процессором; точнее на дальних машинах |

Файлы — в выпусках репозитория YOLOX на GitHub (`Megvii-BaseDetection/YOLOX`, раздел Releases). На блоке модель
лежит в `/opt/urban/models/`. Подойдёт любой экспорт YOLOX: размер входа читается из файла.

**Что не проверено:** точность на настоящем видео Ферганы — ночью, в дождь, против солнца, на дальних 60–100 м.
Это испытание А на стенде (`docs/pilot-kit.md`): запись с реального подъезда, ручной подсчёт наблюдателем,
сравнение. Скорее всего, для дальних машин понадобится `yolox_s` или дообучение на местном видео.

## Первая проверка на настоящем видео (15 октября 2026)

`yolox_nano.onnx` на 15-секундной записи перекрёстка в Чиангмае (Wikimedia Commons, автор Amada44, CC BY-SA 4.0),
1280×720, 4 кадра в секунду, процессор обычного ноутбука:

| | |
|---|---|
| скорость | 18 мс на кадр (медиана), максимум 29 мс — запас примерно в 10 раз для четырёх камер по 4 кадра |
| найдено за кадр | 3–10 машин, в среднем 5,9; легковые 280, мотоциклы 63, грузовики 20 за 62 кадра |
| уверенность | медиана 0,70 |
| ложных срабатываний | на кадре из случайного шума — 0; на видео заметных нет |

Где nano ошибается: машины дальше примерно 60–80 м почти не видит; две машины вплотную (микроавтобус и пикап)
сливаются в одну рамку; мотоциклист в потоке иногда пропущен. Для очереди это значит: хвост длинной очереди
занизится, а стоящие вплотную машины — нормальны (правило очереди смотрит на разрывы, а не на число рамок).

Чего эта проверка **не** показывает: съёмка с уровня глаз, а не со столба 8–10 м — длину очереди в метрах на ней
не измерить. Это испытание А на настоящем подъезде Ферганы; там же решится, хватит ли nano или нужна `yolox_s`.

## Камеры и калибровка

Файл `/etc/urban/cameras.json` на блоке — какие камеры есть и какой подъезд видит каждая. Его пишет страница
калибровки, руками править не нужно.

```bash
# на блоке
python -m urban.vision setup --cameras /etc/urban/cameras.json --unit edge-J-07
# на ноутбуке монтажника
ssh -L 8090:127.0.0.1:8090 urban@<адрес блока>
```

Блок печатает адрес с одноразовым ключом — открыть его в браузере ноутбука. Страница слушает только сам блок;
без ключа она не открывается. На странице:

1. **Добавить камеру:** имя (`cam-1`), адрес потока, подъезд из паспорта перекрёстка (список приходит с комплектом
   блока), число полос, ширина полосы, длина зоны. Пароль камеры в адресе не пишется: `rtsp://${CAM1_USER}:${CAM1_PASS}@10.0.0.11/stream1`,
   а сами значения — в env-файле блока.
2. **Отметить четыре точки** на кадре: левый и правый конец стоп-линии, затем две точки дальней линии напротив
   них (разметка, опора, отметка рулеткой). Ввести расстояние от стоп-линии до дальней линии.
3. **Проверить:** поверх кадра рисуются полосы, стоп-линия, граница зоны и найденные машины. Полосы должны лечь
   на дорогу. Не легли — «Отметить заново».

Камера без калибровки ничего не измеряет и подъезд по ней остаётся «нет данных».

## Запуск на блоке

```bash
sudo -u urban /opt/urban/.venv/bin/pip install -e "/opt/urban/backend[edge,vision]"
sudo systemctl enable --now urban-vision@edge-J-07     # deploy/urban-vision@.service
```

Служба пишет `/run/urban/q/queues.json`; служба блока `urban-edge@` читает его (`SENSORS` в env-файле).

## Проверка на записанном видео

Перед улицей — запись с того же подъезда через тот же конвейер:

```bash
python -m urban.vision check --video approach.mp4 --camera cam-1 --cameras cameras.json \
    --model yolox_nano.onnx --out-video checked.mp4 --log queues.csv --t0 <время начала записи>
python -m urban.bench accuracy --log queues.csv --observed observed.csv
```

`checked.mp4` — то же видео с полосами, рамками машин и очередью: сразу видно, где сеть ошибается. `queues.csv`
сравнивается с подсчётом наблюдателя (испытание А, порог — 15 % или две машины). Записи остаются у инженера, в
платформу не загружаются.

## Приватность

- Кадры — только в памяти блока и только на время распознавания. Записи нет.
- Картинку видит лишь человек у шкафа на странице калибровки, по одноразовому ключу.
- Платформа получает число метров на подъезд раз в секунду. Ни кадров, ни рамок, ни треков.
- Нейросеть ищет только транспорт; номера и лица не распознаются.
