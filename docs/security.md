# Управление и безопасность: проект

Статус: проект. В макете уже работают ступень 2 для одной команды (перенос зелёного между фазами) на эмулированных
светофорах: решение оператора, аренда с автооткатом, политика, аварийные кнопки, журнал аудита, токен оператора.

## 1. Принцип: платформа предлагает, оборудование решает

Платформа никогда не становится единственным «мозгом» объекта. У каждого светофора, насоса,
подстанции остаётся собственный локальный контроллер с базовой программой (фиксированный план,
аппаратные защиты). Платформа может лишь временно скорректировать его работу в заданных пределах.

Из этого следует главное свойство: **если платформа пропала, взломана или ошиблась, объект сам
возвращается к своей базовой программе.** Ни одна команда не должна требовать «отмены» от платформы.

## 2. Откат при сбое: команды с арендой (lease)

Каждая команда живёт ограниченное время и сама истекает.

| Правило | Что значит |
|---|---|
| Срок жизни (TTL) | команда выдаётся на 1–10 минут; продлевается только повторной выдачей |
| Тишина = откат | нет продления, пропала связь, остановилась платформа: объект сам возвращается к базовой программе |
| Пределы допустимого | границы задаёт сторона оборудования, а не платформа (например, зелёная фаза не короче X секунд, нагрузка не выше Y) |
| Отказ от несовместимого | контроллер отвергает команду, нарушающую его аппаратные блокировки (конфликтующие зелёные и т.п.) |
| Кнопка отмены | оператор или аварийный выключатель мгновенно отзывает все активные аренды |
| Последняя исправная конфигурация | перед первой командой фиксируется состояние объекта, откат возвращает именно его |

Откат живёт в контроллере объекта. Если он зависит от платформы, это не откат.

## 3. Ступени допуска к управлению

Переход на следующую ступень делается отдельным решением, с проверкой на реальных данных.

1. **Shadow** (пилот): предложения только записываются в журнал, наружу ничего не уходит.
   Сравниваем, что предложила бы платформа, с тем, что сделали люди.
2. **Подтверждение человеком**: команда уходит, только если оператор нажал «применить».
   Для опасных классов команд подтверждают двое (правило двух ключей).
3. **Ограниченное автоуправление**: платформа сама применяет узкий набор безопасных команд
   (например, продление зелёной фазы на ±10 с) в пределах из п. 2; всё остальное по ступени 2.

Команды, влияющие на жизнь и безопасность (отключение подстанций, насосов водоснабжения,
экстренные режимы светофоров на перекрёстках с трамваем и пешеходами), остаются на ступени 2
и выполняются людьми по регламенту.

## 4. Модель угроз

| Кто и как нападает | Чем защищаемся |
|---|---|
| Взлом платформы через интернет | платформа не открыта в интернет; доступ операторов через защищённый шлюз и VPN, многофакторная аутентификация |
| Украденная учётная запись оператора | роли с минимальными правами, MFA аппаратным ключом, вход по времени и месту, правило двух ключей, быстрый отзыв |
| Недобросовестный сотрудник | журнал, который нельзя править задним числом (цепочка хэшей, копии во внешнее хранилище), разделение ролей: кто предлагает, кто утверждает |
| Подмена данных датчиков (чтобы вызвать неверное решение) | проверка значений на правдоподобие, сопоставление источников, подписи на уровне устройства, отказ от автоуправления при расхождении |
| Подделка команды в сети | подписи команд, взаимная аутентификация (mTLS), защита от повтора (одноразовые номера), одноразовая метка времени |
| Вредоносное обновление или библиотека | подписанные сборки, SBOM, закрепление версий, сканирование зависимостей, проверка в изолированной среде |
| Вымогатель или шифровальщик | копии вне сети, быстрое восстановление, платформа не критична для работы города |
| Отказ в обслуживании | ограничение нагрузки, платформа вне контура реального времени, объекты работают автономно |
| Утечка персональных данных | данные не собираются (камеры отдают счётчики, не лица и номера), хранение в стране, шифрование, минимальные сроки |

## 5. Архитектура защиты

**Сегментация сети** (по модели Purdue / IEC 62443):

```
интернет ─X─  (нет входящих соединений к платформе)
   │
 шлюз операторов (VPN, MFA, запись сеансов)
   │
 зона платформы (анализ, интерфейс, хранилище)
   │  односторонний канал данных (источники -> платформа)
 зона обмена (брокер, адаптеры к оборудованию)
   │
 Command Gateway (единственный путь команд, отдельная зона)
   │  только разрешённые типы команд
 зона оборудования (контроллеры, SCADA), собственная защита
```

- **Данные идут вверх, команды вниз только через шлюз.** Платформа не имеет прямого сетевого
  пути к оборудованию.
- **Command Gateway** проверяет каждую команду по политике: разрешённый тип, объект, диапазон,
  частота, время суток, подпись, утверждение. Отклонённое пишется в журнал.
- **Секреты и ключи** хранятся в аппаратном модуле (HSM) или менеджере секретов, не в коде и не в `.env`.
- **Принцип минимальных прав** для каждой службы: источник не может читать журнал, интерфейс не может выдавать команды.

## 6. Что должно быть до включения хоть одной реальной команды

- Независимый тест на проникновение и обзор кода.
- Отработанный сценарий «платформа пропала»: проверка, что каждый объект возвращается к базовой программе.
- Учения по реагированию на инцидент и по аварийному отключению управления.
- Согласование с владельцами объектов и регулятором; уточнить местные требования по защите критической
  информационной инфраструктуры (КИИ) и по хранению данных. Здесь не указаны конкретные нормы,
  их нужно сверить с действующим законодательством.
- Круглосуточное наблюдение: журналы событий безопасности, оповещения, дежурный.

## 7. Чего нельзя пообещать

Абсолютной защиты нет. Честная формулировка для заказчика: платформа построена так, что её
компрометация **не может остановить город**, а ущерб от неё **ограничен пределами, которые задаёт
оборудование**, и все действия фиксируются.
